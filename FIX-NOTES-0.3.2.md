# DIM 0.3.2 — что исправлено

## 1. Почему в Telegram / Discord / AIDA64 оставался оригинальный iPhone 6s

Твик читал профиль **один раз при запуске процесса** и только напрямую из файла:

```
/var/mobile/Library/Preferences/com.dim.manager.runtime.plist
```

App Store-приложения работают в песочнице: прямое чтение этого пути им запрещено.
`DIMReadRuntime` возвращал `nil`, конструктор выходил на строке
`runtime config not readable` — и **хуки вообще не устанавливались**.
Отсюда оба симптома сразу: в приложениях оригинальная модель и Check никогда
не получает beacon (пишет «откройте приложение в фоне»).

Плюс сам Settings тоже в песочнице, поэтому запись этого файла могла молча не
происходить — то есть конфига могло не быть физически.

**Исправлено:**

* конфиг пишется в домен `com.dim.manager`, ключ `Runtime`
  (`DIMWriteRuntime` в `DIMRuntime.h`);
* внутри приложения читается через `CFPreferencesCopyValue`
  (cfprefsd, песочница не мешает), файл оставлен как резерв;
* отсутствие конфига больше не отключает твик — хуки ставятся всегда,
  а значения подставляются в момент вызова.

## 2. Профиль применяется без перезапуска приложения

`DIMWriteRuntime` теперь посылает darwin-уведомление `com.dim.manager.changed`,
приложение перечитывает профиль и сразу отдаёт новые значения (плюс обновление
при выходе из фона). Перезапуск всё ещё нужен только тем приложениям, которые
кешируют device info в памяти.

## 3. Дырки в поверхностях, по которым приложения смотрят модель

Раньше подменялись только `sysctl` / `sysctlbyname` / `uname` / `UIDevice`.

Добавлено:

* **MobileGestalt** — `MGCopyAnswer`, `MGGetStringAnswer`
  (`ProductType`, `HWModel`, `DeviceClass`, `ProductVersion`, `BuildVersion`).
  Именно через него модель читают App Store-приложения (AIDA64 и т.п.);
* `kern.osproductversion` (строка версии iOS, а не только build);
* `__sysctl` (низкоуровневый вариант);
* `NSProcessInfo operatingSystemVersion`, `operatingSystemVersionString`,
  `isOperatingSystemAtLeastVersion:`.

Символы теперь разрешаются через `dlsym(RTLD_DEFAULT, ...)`, а не через `&func`
(адрес мог указывать на stub, и хук работал бы только внутри твика).

## 4. Check стал диагностическим

Два beacon'а на приложение:

* `com.dim.alive.<bundle>` — твик вообще загрузился в процесс;
* `com.dim.verify.<bundle>` — хеш значений, которые приложение видит **сейчас**.

Статусы в Check:

| Строка | Значение |
| --- | --- |
| `SPOOFED` | всё работает |
| `NOT INJECTED` | твик не загрузился в процесс (фильтр / jailbreak / приложение не открывали) |
| `INJECTED, NOT APPLIED` | твик есть, профиль не применился |
| `MISMATCH` | приложение показывает другие значения — убить и открыть заново |

Check делает второй проход через 1.2 с (приложения успевают получить уведомление),
и в отчёте видно источник runtime-конфига и сколько приложений реально «живые».

## 5. Порядок проверки

1. Settings → Device Identity Manager → **Device Identity** вкл.
2. Выбрать устройство + iOS → **Apply All**.
3. Свайпом убить Telegram / Discord / AIDA64 (не просто свернуть).
4. Открыть их заново → **Check**.

Если в Check по всем приложениям `NOT INJECTED` — проблема в инъекции
(фильтр `DIMCore.plist`, ElleKit/Substrate, «Allow tweak injection» в настройках
джейлбрейка), а не в профиле.
